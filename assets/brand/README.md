# 品牌资产：应用图标与加载动画

> 出处：设计稿 `Daybook Icon Concepts.dc.html`（Claude Design 项目「Daybook桌面端icon设计」）**Turn 12 · 方案 12d「接触阴影」** 定色定形（2026-08-12），**Turn 13 · 方案 13a「平移居中」** 定位（2026-08-13）。
> 本目录是图形的**事实源**——改图标先改这里，再改任何引用它的地方。

## 一句话

三张收据摞在一起，最上面那张正被抽出来——它表现的是 Daybook 的**回溯优先**：生活可以先发生，记录可以后来补。

## 文件

| 文件 | 是什么 | 用在哪 |
|---|---|---|
| [`icon.svg`](./icon.svg) | 512 主图标，静止态 | ≥128px：应用图标、关于窗口、README |
| [`icon-64.svg`](./icon-64.svg) | 中号减配（去掉两行正文，保留抬头栏与一条线） | 48–128px：Dock、窗口标题栏 |
| [`icon-32.svg`](./icon-32.svg) | 小号减配（只剩三张纸的轮廓与撕口） | ≤32px：菜单栏、favicon、文件图标 |
| [`loading.svg`](./loading.svg) | 加载动画（图形与 `icon.svg` 同一套几何） | agent 解析中、导入中的等待态 |

**三档不是同一张图的缩放，是逐级减配。** 512 档的两行正文在 32px 下会糊成一团灰，所以 32 档直接不画——用浏览器打开三个文件、把窗口缩到对应尺寸即可复核。

`loading.svg` 在静止态（`prefers-reduced-motion: reduce`）与 `icon.svg` 逐像素一致，这是刻意的：加载动画停下来就是图标本身。

## 色板

四个主色 + 三个影色，**没有黑**。深棕同时兼任底层纸和所有文字线条。

| 用途 | Hex | 说明 |
|---|---|---|
| 底板 | `#F1EFEA` | 圆角方板的纸白底 |
| 底层纸／墨 | `#4E2F1C` | 最下面那张纸，同时是全部线条与抬头栏的颜色 |
| 中层纸 | `#C4B79C` | 麻色；也用作深棕纸上的反白线条 |
| 顶层纸 | `#A9C6E8` | 蓝 |
| 影·纸白上 | `#AD9E93` | 以下三个是 `#4E2F1C` 按 42% 压在各自承影面上的**实际合成值** |
| 影·麻上 | `#927E66` | |
| 影·蓝上 | `#838793` | |

**SVG 里写的是 `opacity=".42"` 的半透明影，不是上面三个实色。** 这是有意的——影色**按承影面走**，而一张纸的影常常同时跨在两种底色上（如中层纸的影一部分落在深棕纸、一部分落在纸白底）。用 alpha 合成，每一处自动得到正确的值；写死实色则每跨一次界就要再切一块。

上表三个实色的用途是**需要纯平色的场合**：印刷、限色导出、以及任何不支持透明度的媒介。此时按承影面逐块替换，跨界处另取值。

## 几何

- 底板：512 × 512，圆角 `rx = 23%`（即 `117.76`），四角外透明
- 纸堆整体：`translate(…) rotate(-11 256 256) skewX(-9)`——**从右往左读**：先切再转得到纸堆，最后整体平移到画布正中。三个变换的顺序都不能反
- 三张纸同宽同高，纵向每层相隔 86（512 档：y = 96 / 182 / 268）
- 每张纸的下缘是**撕口**（锯齿折线），不是直边
- 每张纸的影 = 同一条路径 `translate(6 16)`（512 档；64 档 `(8 18)`、32 档 `(10 22)`——尺寸越小影越要拉开才看得见）

### 平移量：每一档各算各的

`rotate` 的支点是画布中心，但纸堆本身并不以画布中心为中心——转完之后它整个偏在左下，右上空一大块。**13a 只做一件事：加一个最外层 `translate`，把纸堆的包围盒中心挪到 (256, 256)。形状零改动。**

| 档 | 包围盒（含影） | 平移量 | 实测中心 |
|---|---|---|---|
| 512（`icon.svg` / `loading.svg`） | 210 × 368 | `translate(44.5 -10)` | (256.0, **258.0**) |
| 64（`icon-64.svg`） | 228 × 392 | `translate(41.4 -22.8)` | (256.0, 256.0) |
| 32（`icon-32.svg`） | 247 × 412 | `translate(38.3 -30.2)` | (256.5, 256.0) |

**三档的平移量不同，因为三档的纸不一样宽**——减配档为了在小尺寸看得清，纸画得更宽、影拉得更开，包围盒也就更大。**照抄 512 档的 `44.5 -10` 会让 32 档偏出去 10 个单位。**

512 档写的是设计稿 13a 的原值，因此 y 上比正中低 2 个单位（设计稿自身的取整）——0.4%，在 29px 的 lockup 上是 0.11px。**保留原值是为了让这份实现能和设计稿逐字对上**；另两档设计稿没有给值，按同一条规则（包围盒含影 → 中心对到 256）算出来。

复核方式：把底板那行 `<rect>` 删掉再渲染，量剩下内容的包围盒——

```bash
# 需要一个尊重 transform 与 clipPath 的渲染器；macOS 上用 Chrome headless
magick np-icon.png -format "%@" info:    # → 210x368+151+74，中心 (256.0, 258.0)
```

**别用 ImageMagick 自带的 MSVG 渲染器**（未装 `librsvg` 时 `magick foo.svg` 就会落到它上面）：它会丢掉 `transform` 与 `stroke`，渲出来是一张不转不切、没有影也没有正文行的图。2026-08-13 之前 `src-tauri/icons/icon.png` 正是这么来的——它和 `icon.svg` 根本不是同一张图，而**没有任何一条门禁会发现**（`app_icon_decodes_to_eight_bit_rgba` 只查位深）。

**零描边。** 三层靠明度差与接触阴影分开，不靠黑边——描边是补丁，根因是麻与蓝的明度太接近（设计稿 Turn 12 的结论）。

## 动效规格

| 动画 | 周期 | 缓动 | 做什么 |
|---|---|---|---|
| `db-pull` | 5.4s | `cubic-bezier(.3, 0, .3, 1)` | 12%–28% 时 `translate(66px, -40px)`，其余归位 |
| `db-row` | 2.2s | `ease-in-out` | 顶层两行正文在 `opacity` `.16` ↔ `1` 之间闪 |

- **错拍**：顶层（蓝）延迟 `0`、中层（麻）`1.8s`、底层（棕）`3.6s`——一个周期里三张纸依次被抽出又放回，永远只有一张在动
- 第二行正文比第一行延迟 `.2s`，避免两行同步闪烁像故障
- 抽出的纸**从后面走**（绘制顺序不变），所以底层纸抽出时仍被上两张挡住一部分——这是纸堆该有的物理，不是层级错误

### 无障碍

`loading.svg` 内联了 `@media (prefers-reduced-motion: reduce) { animation: none }`。系统开了「减弱动态效果」时它停在归位态，不闪、不动。**不要在引用处再加一层动画**——那会绕过这条。

## 引用方式

图形是**自包含的 SVG**：无外链字体、无 `<script>`、无任何网络请求，符合仓库根 [`CLAUDE.md`](../../CLAUDE.md) 约束 2「数据不出本机」。可以直接 `<img src>`，CSS 动画在 `<img>` 里照常运行。

`loading.svg` 的底板是单独一行 `<rect id="db-plate-bg">`。**内嵌到应用界面里当等待态时把这一行删掉**，纸堆就直接落在应用自己的背景上，不带一块突兀的浅色卡片。

## 平台图标

现状只有一张 `src-tauri/icons/icon.png`（1024 × 1024，8 位/通道 RGBA），由 `icon.svg` 光栅化而来；`.icns` / `.ico` / 各尺寸 PNG **还没生成**，`bundle.active` 也仍是 `false`。

改了 `icon.svg` 就要重新光栅化这张 PNG，否则应用图标和事实源对不上：

```bash
# 1. 光栅化。渲染器必须尊重 transform 与 clipPath；macOS 上用 Chrome headless：
#    页面里放一个 1024×1024 的 <img src="icon.svg">，透明底截图
#    （不要用 `magick icon.svg out.png` —— 见「几何 · 平移量」那一节）
# 2. 落到 src-tauri/icons/icon.png，然后跑：
cargo test m0::app_icon_decodes_to_eight_bit_rgba   # 必须 8 位/通道，否则应用启动即 abort
```

M4 打包时 `npm run tauri icon <1024 PNG>` 才会生成整套 `.icns` / `.ico`。届时两个已知问题一起解决，现在不猜：

1. **macOS 的边距**：系统图标约定是画布留约 10% 边距、圆角用 Apple 的超椭圆（squircle）而非正圆角。本图标是满幅 `rx=23%` 圆角方，直接送进 Dock 会比邻居显大一圈，圆角曲率也略有差异。
2. **减配档怎么进 `.icns`**：`tauri icon` 只会把一张源图逐级缩放，不会自动换用 `icon-32.svg`。要让小尺寸用减配档，得手工组 iconset。
