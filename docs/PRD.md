# Daybook 总 PRD

> **一句话**：Daybook（日簿）是一个跑在本地的 AI 桌面助手，帮你把「过去这段时间的钱和事」补记回来。
> 本文定义**做什么、做到什么算成功、明确不做什么**，以及里程碑与各 sub-PRD 的对应关系。**范围变更必须先改本文。**
> 结论来源：2026-08-06 立项讨论，已由产品负责人逐条确认。技术选择的完整论证在 [`docs/adr/`](./adr/)；术语定义在 [`docs/CONTEXT.md`](./CONTEXT.md)；系统结构在 [`docs/architecture.md`](./architecture.md)。

## 1. 问题与核心洞察

痛点**不是**「记一笔账要点五下」，而是——

> **隔了 7 到 10 天，我得回过头去把这段时间发生的事一件件挖出来。**

这一句是整场立项讨论的转折点，也是本产品全部设计的起点。它有三个直接推论：

1. **AI 的角色是考古学家，不是输入框。** 从痕迹里把过去还原出来，摆到用户面前，用户只负责审。核心动作是**重建**，不是**录入**。
2. **产品气质是低频、重型、有仪式感**（一两周一次的「财务体检」），不是日常高频工具。
3. **它救不了「懒得动」，只救「动了之后很痛苦」。** 用户依然要花 3–5 分钟在手机上截图；产品把之后的一小时压成十几分钟。

## 2. 用户

**主用户是「明知该记但当场记不了、只能事后补」的人。**

**第一优先场景是跨境双币种生活**——澳洲银行卡 + 信用卡 + 微信 + 支付宝并行。这是国内与海外记账工具都覆盖不到的夹缝：国内 app 看不懂 CBA（Commonwealth Bank of Australia）对账单，海外 app 不知道微信支付宝是什么，「人民币换澳元按当时汇率入账」两边都不管（依据 §10 竞品调研）。

v1 不服务：多人协作、家庭共享账本、企业报销、需要移动端随手记的高频用户。

## 3. 三个支点

1. **用户自带 AI 额度 → 边际成本为零 → 可以暴力啃任意格式截图。**
   传统记账 app 必须给每家银行写专用解析器（银行改格式就挂、长尾永远覆盖不到）；按 API 计费的竞品算完账也会退回去写解析器。**只有本项目能对着任意截图直接说「读吧」。**
2. **接 Claude Code / Codex → 白捡一个 agent 内核。**
   用户要的是「下达任务、它自己编排」，这两个 CLI 本身就是成熟 agent runtime。这也是**必须桌面端**的理由：要调本地登录态、本地进程、本地文件（[ADR-0003](./adr/0003-agent-runtime-and-pluggable-backend.md)）。
3. **本地优先 + 无账号 + 无后端 + 语音也本地。**
   账目和日程极私密。数据不出本机 → 隐私天然过关、无各国合规问题、零服务器成本——**这是一个人能扛得动的唯一形态**（[ADR-0001](./adr/0001-local-first-desktop-platform.md)）。

## 4. 生死线：AI 永不直接写入账本

视觉模型**真的会把 168 读成 1680**，账本错一个数字用户信任就永久归零。四道闸门（完整论证与实现要求见 [ADR-0002](./adr/0002-ai-never-writes-directly.md)）：

| 闸门 | 要求 | 为什么 |
|---|---|---|
| **草稿区** | AI 只写 `draft_*` 表，人确认才由确认动作写事实表 | 任何绕过草稿区的写入路径都是缺陷 |
| **证据链** | 每条草稿挂 `source_id`（哪张截图/哪个文件）+ 原文片段；审核界面原文与解析结果并排 | 把「信任 AI」换成「扫一眼原文」 |
| **总额交叉校验** | 从一个来源拆出的条目合计，必须与该来源自身声明的合计/余额核对；不符显式报警并阻止批量入库 | **唯一能在无人工介入下捕获错误的机制，优先级高于解析准确率本身** |
| **审计日志** | append-only，记「谁 / 何时 / 把什么改成了什么」 | 出错时能回溯到具体那一次写入 |

## 5. v1 范围

**原则：「交易」做深，「事项」做薄。**

### 5.1 深：交易

截图导入 → 解析重建 → 证据链 + 总额校验 → 审核 → 入库 → 基础回顾。**做到能真正替代手工流程。**

- 多图批量导入，跨图去重
- 多币种：存**原币金额 + 本位币金额 + 当时汇率**三元组，不逼用户手算（[ADR-0004](./adr/0004-data-model-sqlite-integer-money.md)）
- 商户、分类、渠道
- **审核界面是胜负手**：整个产品省下的时间全兑现在这一屏。密集表格、原文并排、异常项排最前、默认全选、键盘走完。**做成 30 秒是成功，做成 20 分钟这产品就没意义。**
- 基础回顾：这段时间钱花在哪了

### 5.2 薄：事项

一条记录走完整生命周期：`backlog（无日期）→ 排到某天 → 完成（带实际时长）→ 未完成退回 backlog`。**「待办」和「时间日志」是它的两端，不是两个功能。**

- backlog 列表、一句话批量丢入
- 拖到某天、记完成时段
- 能回答「这周时间花哪了 / 什么没做完」

### 5.3 贯穿

- **时间轴是共同骨架，但 UI 分两个视图**——不在同一张日历里混着显示钱和时间
- **记忆系统存规则，不存对话**：商户→分类映射、用户的每次纠正、个人语境词表、语音专有名词表。**这是唯一的复利**：第一个月 40 条改 8 条，半年后 40 条改 1 条
- **交互形态是「对话下指令 + 界面做审核 + 界面看回顾」**，不是聊天框包打天下。语音只用于输入，绝不用于审核（没法用嘴说「第 7 条金额改成 168」）

## 6. 非目标（v1 明确不做）

| 类别 | 不做的东西 | 说明 |
|---|---|---|
| 事项功能 | 提醒、重复任务、子任务、优先级算法、番茄钟 | 「薄」的字面含义 |
| 采集 | 弱信号采集（git / 日历 / 浏览器历史 / 屏幕使用时间） | 未来做，但必须逐项授权、默认全关（[ADR-0005](./adr/0005-voice-and-system-integration.md)）；届时应接 [ActivityWatch](https://github.com/activitywatch/activitywatch) 而不是自己造 |
| 闭环 | 意图↔事实闭环（待办「交房租 2000」自动被账单里的 2000 转账核销） | **v2 的奖励，不是 v1 的门票**，见 §11 |
| 数据 | 历史数据导入 | |
| 平台 | 手机端、Windows/Linux 发行 | Tauri 保留后路，v1 只做 macOS |
| 形态 | 任何形式的同步、账号、后端、变现 | 与「本地优先」是同一条约束 |
| 代码 | v1 写任何 Swift | 语音用 macOS 系统听写；sidecar 推 v1.1（[ADR-0005](./adr/0005-voice-and-system-integration.md)） |

## 7. 成功标准

- **一个月**：用它补过 3 次账，**且没有一次因为不放心而回去翻原始截图核对**。（一旦开始偷偷复核，它就已经失败了）
- **终点**：不再打开原来的记账软件和日程软件。
- **审核界面单点指标**：40 笔 30 秒审完。

## 9. 里程碑地图

| 里程碑 | 涉及 sub-PRD | 判定标准 |
|---|---|---|
| **M0** 端到端点亮 | [`00`](./prd/00-foundation.md) + [`01`](./prd/01-agent-runtime.md) + [`02`](./prd/02-ingest.md) + [`03`](./prd/03-review.md) 各取最小切片 | 拖一张截图 → agent 读 → 经 MCP 入库 → 列表显示。**端到端跑通，丑无所谓** |
| **M1** 审核界面 | [`03`](./prd/03-review.md) 做深 | 40 笔 30 秒审完 |
| **M2** 批量与多币种 | [`02`](./prd/02-ingest.md) + [`04`](./prd/04-transactions.md) | 一次处理真实的 10 天（多图批量、跨图去重、多币种 + 历史汇率） |
| **M3** 事项与记忆 | [`05`](./prd/05-items.md) + [`06`](./prd/06-memory.md) | backlog → 拖到某天 → 记时长；纠正能沉淀成规则 |
| **M4** 可插拔与打包 | [`01`](./prd/01-agent-runtime.md) 补全 | 别人能跑起来（可插拔 agent 后端补全 + 打包 + README） |

### 9.1 为什么 M0 优先

**M0 能验掉最大的未知数**：视觉模型读澳洲银行截图到底准不准。这个问题的答案决定整个产品成不成立，必须最先撞。

### 9.2 M0 各 sub-PRD 取哪一片

M0 天生横跨多份 sub-PRD——walking skeleton 就是这样。各份取最小切片：

| sub-PRD | M0 切片 | M0 **不**做 |
|---|---|---|
| [`00-foundation`](./prd/00-foundation.md) | SQLite 打开 + 迁移运行器 + `sources` / `draft_transactions` / `transactions` / `audit_log` 四张表 + 错误契约 | 完整 schema、事项相关表、记忆表 |
| [`01-agent-runtime`](./prd/01-agent-runtime.md) | 起 MCP server（stdio）+ spawn `claude -p` + 两个工具（写草稿、查来源） | 可插拔后端的第二个实现、子 agent 上下文隔离 |
| [`02-ingest`](./prd/02-ingest.md) | 拖入单张截图 → 落 `sources` + 证据文件 → 触发一次解析 | 多图批量、跨图去重、文件监听 |
| [`03-review`](./prd/03-review.md) | 一个能看到草稿并逐条确认入库的最朴素列表 | 键盘流、原文并排、异常前置、虚拟滚动 |

## 10. 竞品与差异化（调研结论，2026-08-06）

- **国内移动端是红海**：账明、一木记账、咔皮记账、AI 记账本、百事 AA 记账——「AI 截图记账 + 语音记账 + 对话分析」全部有人做且免费。**「AI 记账」本身不是差异化。**
- **海外开源集体回避 AI**：Actual Budget（本地优先、有 AI 查询）、Firefly III（**官方立场就是「不要黑盒机器学习」**）、ezBookkeeping、CurioPay。这反证了「AI 不敢写账本」是真实的坎——本项目的证据链 + 总额校验正是绕过它的路（§4）。
- **时间追踪**：[ActivityWatch](https://github.com/activitywatch/activitywatch)（开源、本地优先、跨平台、可写自定义 watcher）是弱信号采集的现成基础设施，**未来应当接它而不是自己造**；它只做「自动采集」不做「人工补录」，也不碰钱——中间那层「把机器活动翻译成人类事项」正是本项目该加的价值。
- **结构性护城河**（不是包装，是对手做不到）：① 竞品商业模式依赖云，「数据不出本机」做了就没饭吃 ② 竞品自己付 token 钱，做不起重解析 ③ 竞品是记账公司，不做钱与时间同轴。

## 11. 终局价值（v2 方向，不进 v1）

待办写着「这周交房租 2000」，账单里出现一笔 2000 转账 → 待办自动打勾、预算自动核销。**意图与事实互相印证**——这是分成两个 app 永远做不到的事，也是「一个 app」的真正理由。

**但这是 v2 的奖励，不是 v1 的门票。** v1 只需保证数据形状（一条时间轴 + 两个实体）不挡住 v2 的路。

## 12. 需要清醒接受的三件事

1. **它救不了「懒得动」，只救「动了之后很痛苦」。**
2. **时间日志做不到「几点到几点」。** 钱有客观痕迹，时间没有。只能粗粒度——好在**时间容忍模糊，钱不容忍**。
3. **入门级会员的用量限制是真实约束。** 核心操作（多图 + 长上下文 + 多轮推理）恰好最烧额度。

### 平台风险（已知，不写进产品叙事）

Anthropic 对第三方 agent 使用订阅额度的政策反复过：2026-04-04 封禁 → 05 月改为 Agent SDK credits（按 API 价计费）→ **06-15 暂停该改动**（当前 `claude -p` 与第三方 app 仍走订阅额度）。方向明确但未落地。**对策就是可插拔后端接口（[ADR-0003](./adr/0003-agent-runtime-and-pluggable-backend.md)），不需要在 README 或定位里反复强调。**
