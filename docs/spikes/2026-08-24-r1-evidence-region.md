## 问题与通过线

[`03-review.md` §3.2](../prd/03-review.md) 希望点一条草稿时在来源截图上高亮对应交易行。这个高亮属于证据闸门：**稳定地指错相邻行，比没有高亮更危险**。因此不能只看「模型是否返回了四个数」，而要同时看正确行命中与相邻行侵入。

开跑前采用以下 fail-closed 门槛；任一不满足就不把坐标放进生产 schema：

- 坐标结构合法率 100%；
- 危险误定位观察值 ≤ 0.5%，按来源聚类的一侧 95% 上界 ≤ 1%；
- 相邻行侵入超过预测高度 10% 的比例必须为 0；
- vertical IoU 中位数 ≥ 0.80、p10 ≥ 0.60；
- 同一真值行三轮的 y 中心跨度 p95 ≤ 0.25 个真值行高；
- 无法唯一定位时允许 `null`，不允许猜。

2D IoU 只作诊断，不作唯一门槛：一个横向较窄但落在正确行内的高亮已经能帮助核对，反之一个很大的框可能有高 IoU 却侵入相邻行。

## 两层探针

### 1. 快速视觉对照

先用 Claude Code 的本地图片引用直接把 7 张图交给 `claude-sonnet-5`，每图 3 个独立会话；分别测：

1. 完整 `[left, top, right, bottom]`，坐标归一化到 `0..1000`；
2. 只报一个归一化 `centerY`，排除「四个边界太难」这个解释。

这层不冒充产品链路，只回答「同一 CLI 的另一个当前模型是否具备稳定坐标能力」。

| 形状 | 预测数 | 结构合法 | 正确行中心命中 | 相邻行侵入 >10% | p95 中心误差 | p95 三轮中心跨度 |
|---|---:|---:|---:|---:|---:|---:|
| bbox | 240 | 233 / 240（97.08%） | 69.53% | 39.91% | 98.3 / 1000 | 173.85 / 1000 |
| center-only | 240 | 240 / 240 | 75.00% | — | 67.1 / 1000 | 110.35 / 1000 |

bbox 有一轮把移动端长图的 y 坐标报到 1930，直接违反 `0..1000`；center-only 去掉边界后仍有四分之一落不到真值行。**坐标能力明显依赖模型，且仅缩成一个点也没有变稳定。**

### 2. 产品真实密封链路

随后在一次性 detached worktree 中给 `draft_transaction` 的参数临时增加可空 `evidence_bbox`，只进入 Rust 自动生成的 `drafted_json`，**不做迁移、不改主工作区**。经生产同一路径执行：

```text
Daybook eval → parse_source → 密封 Claude Code
  → read_source（MCP ToolContent::Image）
  → draft_transaction（临时 evidence_bbox）
  → drafted_json → 离线评分
```

冻结条件：

- 工具面版本：`89a63f825c1f9aefe228726747961b8213ecdde9840db72479d68ec66863374e`
- prompt hash：`14505668cfec7005653de7411257a8190968ee5793f6790c7276e7a34b9765fb`
- effective capability hash：`2fd38cecbac7c9240543cb56a9815049451df8eb315851fa431387bfef8097a2`
- 坐标：整张可见原图左上为 `(0, 0)`、右下为 `(1_000_000, 1_000_000)`；完整行/卡片；不确定则 `null`
- 每张图 3 个独立 agent 会话，不复用上下文

外层 30 分钟预算跑完密集列表、移动端卡片、中英混排与深色列表 12 轮中的 11 轮；最后一轮已起草 10 条但在外层截止前未完成协议，因此记为未完成，不把它伪装成成功。共得到 156 个结构合法的 bbox，模型一次 `null` 都没有返回。

| 指标 | 结果 | 门槛 | 判定 |
|---|---:|---:|---|
| 结构合法率 | 100%（156 / 156） | 100% | 通过 |
| 危险误定位 | **0.64%（1 / 156）**；未做来源聚类、口径更宽松的一侧 95% Wilson 上界仍为 **2.82%** | 观察值 ≤ 0.5%，来源聚类上界 ≤ 1% | **失败** |
| 相邻行侵入 >10% | **5.77%（9 / 156）** | 0 | **失败** |
| vertical IoU | 中位数 **0.704** · p10 **0.597** | ≥ 0.80 · ≥ 0.60 | **失败** |
| 三轮 y 中心跨度 | p95 **0.54 个行高** · 最大 **0.61 个行高** | p95 ≤ 0.25 | **失败** |
| 产品轮次完成 | 11 / 12；已完成轮次中位 110.35 s、p95 176.09 s | 本 spike 不单独设性能门槛 | 仅记录 |

最危险的一例来自移动端卡片第 12 行：预测中心落到真值行之外，模型没有选择 `null`。另两轮的同一布局从第 8 行开始逐步向下一行漂移，造成相邻行侵入；这不是给框加 padding 能修好的像素级误差，而是坐标尺度随纵向位置累积漂移。

产品链路当前默认模型的结果远好于 Sonnet 对照，但 Daybook **没有固定某个模型**，且 [ADR-0003](../adr/0003-agent-runtime-and-pluggable-backend.md) 要求后端可插拔。一个只有当前 Opus 配置勉强接近门槛、换成当前 Sonnet 就大幅失效的证据定位契约，不能成为跨后端的 schema 保证。

本轮产品链路的 CLI 费用估算合计约 **USD 6.48**；两组快速对照约 **USD 1.53**。这是用户自己的 CLI 给出的估算，只记录成本，不构成产品侧收费。

## 结论

**R1 关闭为「当前不可稳定定位」。** M1 不增加截图坐标字段、不新增 `0002_*` 迁移、不把 bbox 加进 `draft_transaction`，也不按 `source_ordinal` 猜等高行。

审核界面采用已经存在的安全退路：

- 来源原图默认完整可见；
- 每条草稿继续显示 `evidence_text`，明确它只是抽取声明；
- `utterance` 继续使用可由原文逐字验证的 Unicode code-point span；
- 图片没有可独立验证的定位信号时，不显示一个看似精确但可能指错行的高亮。

未来只有在出现**可独立验证坐标**的能力时重开：例如本地 OCR / layout 引擎先产出可校验文本框，或后端提供有稳定契约且能被代码验证的 grounded vision。仅换提示词、增加模型自评 confidence、或看到一个更强模型暂时跑绿，都不足以重开。

## 怎么复现

1. 按上表尺寸生成带唯一金额的列表/卡片图，同时保存每行真值框；
2. 在临时 worktree 给 `DraftTransactionArgs` 加可空百万分比 bbox，只让它进入 `drafted_json`；
3. 提示词说明整图坐标、完整行语义与允许 `null`；
4. 用 `daybook-eval run --trials 3 --keep-runs …` 从生产密封链路跑独立会话；
5. 按 `source_ordinal` join 真值与预测，计算正确行中心、相邻侵入、vertical IoU 与跨轮跨度；
6. 换 CLI、默认模型或工具 schema 后必须整轮重跑，旧数字不外推。
