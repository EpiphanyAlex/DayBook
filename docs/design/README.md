## 归档时改了什么

**正文与上游逐字一致**（含 `<x-dc>` / `<helmet>` 包裹与全部内联样式），只动了两处，都是被迫的：

**1. 删掉 `<script src="./support.js"></script>`。** 两个独立理由：

- 该运行时**会向页面注入 `https://unpkg.com/react-dom@18.3.1/...` 的 CDN `<script>`**。实测方式是 `--dump-dom` 对比两次渲染的产物。设计稿本身零外链（`grep -o 'https\?://'` 无命中），**把 `support.js` 一起归档反而会给一份纯离线的文件装上远程依赖**，违反 [`CLAUDE.md`](../../CLAUDE.md) 约束 2；讽刺的是设计稿里那句注释「support.js 是本地文件，不是远程依赖」本身就不成立，注释按原样保留未改。
- **它还会把设计稿渲染错。** 设计稿用了 `nav > span[style*="box-shadow: inset 3px 0 #1f5f8f"]` 这类属性选择器，把导航当前项从靛青覆盖成棕墨；React 重新序列化内联样式后（`#e6f2fd` → `rgb(230, 242, 253)`、`inset 3px 0 #1f5f8f` → `rgb(31, 95, 143) 3px 0px inset`），选择器**静默失配**，当前项渲染成蓝底——正好和设计稿自己那句「棕墨负责应用位置、靛青负责用户动作」相反。**去掉运行时之后渲染的才是设计意图。**

**2. 12 处 `src="assets/icon.svg"` 改指 `../../assets/brand/icon.svg`。** 图标的事实源只有一份，见 [`assets/brand/README.md`](../../assets/brand/README.md)（「本目录是图形的事实源」）；上游那份 `assets/icon.svg` 与它是同一张图，不再复制一遍。

**没改的**：文件里两个指向 `Daybook Token System v3.dc.html` 与 `Daybook 桌面端设计稿 v8.dc.html` 的链接**在仓库里是死链**——那两份仍只在 Claude Design 项目里。Token System v3 已经回流成本仓库的 [`design.md`](../../design.md) v0.4（见下一节），v8 稿没有回流需求，所以按原样留着，当作回上游的指针。

## Token 核对：24 个里 22 个逐字一致

设计稿 `:root` 里的 24 个颜色 token，与 [`design.md`](../../design.md)（v0.5，这两档的取值自 v0.4 未变）逐个比对，**22 个完全相同**。两个不一致：

| token | v9 设计稿 | `design.md` | 差在哪 |
|---|---|---|---|
| `ink-800` | `#4e2f1c` | `#463021` | v9 用的是**图标里那支棕的原色**；token 体系里 `ink.800` 是 `oklch(.33 .040 55)` 规整之后的值 |
| `paper-500` | `#c4b79c` | `#c1b6a2` | 同上，图标麻色的原色 vs `oklch(.78 .030 82)` |

**这不是两套配色，是同一套的两个取值口径。** 上游的 Token System v3（= `design.md` v0.4 的来源）自己写明：「取色来源 · 图标里已有的四种颜色：`#4E2F1C` 棕墨 → `ink.800 / 900`；`#C4B79C` 麻 → `paper.500`」——**图标色是推导起点，token 是 OKLCH 规整后的落点**，而九个屏画的时候用回了起点。`ink-800` 承担所有标题、导航当前项与结构线，这个差别在整屏上看得出来。

**口径已于 2026-08-24 定：以 OKLCH 规整值为准，设计稿改这两个 hex。** 决定性理由是上面那句引文自己给的——**`#4E2F1C` 被同时指派给 `ink.800` 与 `ink.900` 两档，一个 hex 充不了两档**，所以「用回原色」在这套体系里不可表达。详见下表第 6 条。

## 设计稿领先于规格的地方（**已于 2026-08-24 全部评审并回流**）

八条已逐条拍定，规格改动已落地。**表里记的是决定，不是待办。**

|---|---|---|---|
| 1 | 账目 **12 个两字分类**，不分收支两栏 | **两字命名采纳，不分收支不采纳。** `scope` 与收入分类保留（`direction` 变更清分类、`transfer` 必须为空这两条硬规则靠它）；默认名由四字改两字；清单重编为**支出 19 + 收入 7**，新增**订阅**（按是否周期续费判）与**美容**（服务，与日用的消耗品分开），`服饰个护`/`数码电器`/`税费保险`/`劳务经营` 四条各自拆开，**税费不再预置**。稿子那 12 条里没有一条收入分类，所以「照稿子来」等于删掉收入侧——这不是两套设计选一套 | [04 §3.3](../prd/04-transactions.md) v0.9 |
