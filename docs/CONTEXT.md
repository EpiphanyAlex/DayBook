# 术语表

> 本文是 Daybook 的**当前术语**。目的：让「没读过那场对话的人」和「无记忆的 agent」在读任何一份文档时，对同一个词的理解一致。
> **词义变了先改本文，再改用到它的地方。** 新增词条时同步检查 [`docs/PRD.md`](./PRD.md)、[`docs/architecture.md`](./architecture.md) 与 [`docs/prd/`](./prd/) 是否有冲突用法。

---

## 产品层

**Daybook / 日簿**
本产品。`daybook` 是会计术语「日记账」——按时间顺序记录原始凭证的簿子；字面又是「每日之书」。

**回溯记录器**
本产品的品类定位。**不是记账 app，不是待办 app。** 服务于「明知该记但当场记不了、只能事后补」的人。核心动作是**重建**，不是**录入**。

**考古学家**
对 AI 在本产品中角色的比喻：从截图等**痕迹**里把过去还原成待确认草稿。与之对立的是「输入框」——那是把 AI 当成一个更快的打字方式。

**财务体检**
用户使用本产品的典型场景：一两周一次，坐下来把过去这段时间的钱和事一次补完。产品气质由此确定为**低频、重型、有仪式感**，而非日常高频工具。

## 数据实体

**交易 / transaction**
一笔钱的流动。字段：金额、币种、汇率、商户、分类、渠道、来源截图。v1 的「深」模块（[`docs/prd/04-transactions.md`](./prd/04-transactions.md)）。

**事项 / item**
一件要做或已做的事。**一条记录走完整生命周期**：

```
backlog（无日期）→ 排到某天 → 完成（带实际时长）→ 未完成退回 backlog
```

**「待办」和「时间日志」是这个实体的两端，不是两个功能**（[ADR-0004](./adr/0004-data-model-sqlite-integer-money.md) §4）。v1 的「薄」模块（[`docs/prd/05-items.md`](./prd/05-items.md)）。

**backlog**
事项生命周期的起点：**已记下但尚未排到某一天**的事项集合。不是「优先级低的事」，只是「还没安排日期的事」。

**来源 / source**
一份被导入的原始材料——一张截图、一个文件。它是证据链的锚点：每条草稿都指向一个 `source_id`。落库时同时保存文件本身（存在数据库旁边的普通目录）与元数据。

**证据 / evidence**
草稿与来源之间的具体连接：`source_id` + **原文片段**（来源上那一行的文本）。**无证据的草稿不得入库**——这是数据层的非空约束，不是 UI 约定（[ADR-0002](./adr/0002-ai-never-writes-directly.md) 闸门 2）。

**草稿 / draft**
AI 产出的**待确认**记录，存在 `draft_*` 表。**AI 只能写这里。** 人工确认后，由确认动作写入事实表。

**事实表**
存放已确认数据的表（`transactions`、`items`…）。**只能由人工确认动作写入**，agent 没有任何可达的写入路径（[ADR-0002](./adr/0002-ai-never-writes-directly.md) 闸门 1）。

**审计日志 / audit_log**
append-only 的变更记录：「谁 / 何时 / 把什么改成了什么」。**只追加，不更新、不删除。**

## 金额与币种

**最小货币单位**
分 / cent。**金额一律以整数存储最小货币单位**，任何位置禁止用浮点数表示金额，包括中间计算与 IPC 传输（[ADR-0004](./adr/0004-data-model-sqlite-integer-money.md) §2）。

**原币 / 原币金额**
交易实际发生时用的货币与金额，**与截图上写的完全一致**。

**本位币**
用户记账的基准货币。跨境场景下所有交易都会折算到它，以便汇总与回顾。是否可切换尚未拍板（[`docs/PRD.md` §13](./PRD.md) 开放问题 P2）。

**三元组**
每笔交易同时存的三个值：**原币金额 + 本位币金额 + 当时汇率**。不得只存换算后的结果（证据链会断），也不得在录入时要求用户手算。单币种交易走同一套，汇率为 1，不设特例（[ADR-0004](./adr/0004-data-model-sqlite-integer-money.md) §3）。

**渠道 / channel**
这笔钱经过的支付通道：澳洲银行卡、信用卡、微信、支付宝……跨境双币种场景下渠道与币种不是同一个维度（同一张卡可能有多币种账户）。

## 校验与审核

**总额交叉校验**
从一个来源拆出的条目，其**合计**必须与**该来源自身声明的合计/余额**核对；不符时**显式报警并阻止批量入库**。

**这是唯一能在无人工介入下捕获错误的机制，优先级高于解析准确率本身**（[ADR-0002](./adr/0002-ai-never-writes-directly.md) 闸门 3）。它依赖整数金额的精确相等，这也是禁用浮点的直接理由。

**审核界面**
产品的**胜负手**——整个产品省下的时间全兑现在这一屏。要求：密集表格、原文并排、异常项排最前、默认全选、键盘走完。**做成 30 秒是成功，做成 20 分钟这产品就没意义**（[`docs/prd/03-review.md`](./prd/03-review.md)）。

**异常前置**
审核界面的排序规则：校验不过的、置信度低的、与历史规则冲突的条目排在最前面。用户的注意力应该花在可疑项上，而不是均匀分给 40 条。

## Agent 与运行时

**agent CLI**
用户**自己已安装并登录**的命令行 agent：Claude Code（`claude -p`）或 Codex（`codex exec`）。应用**不打包任何厂商凭证、不提供第三方登录、不代理厂商鉴权**（[ADR-0003](./adr/0003-agent-runtime-and-pluggable-backend.md) §4）。

**MCP server**
本应用暴露给 agent 的工具面，走 stdio、用 `rmcp`（官方 Rust SDK）实现、**在 Tauri 主进程内起**。**本 app 本质上是一个本地 MCP server**——不让 agent 输出 JSON 再解析，而是用 MCP 暴露工具（[ADR-0003](./adr/0003-agent-runtime-and-pluggable-backend.md) §1）。

**agent launcher**
Rust 侧负责 spawn / 监控 / 回收 agent CLI 子进程的组件。

**工具权限**
MCP 工具的写入范围**在实现层面锁死**：记账工具只能写交易草稿表，事项工具只能写事项草稿表，修正工具带硬规则。**不得提供通用的「执行任意 SQL」类工具。** 权限边界就是工具签名，不是对 agent 的口头要求（[ADR-0003](./adr/0003-agent-runtime-and-pluggable-backend.md) §3）。

**子 agent**
**只用于上下文隔离**（如解析超长截图），**不用于业务分工**。产品运行时不引入多 agent 自主编排（[ADR-0003](./adr/0003-agent-runtime-and-pluggable-backend.md) §2）。

**可插拔后端**
agent 后端的抽象接口：`claude -p` / `codex exec` / 用户自备 API key / 本地模型。**v1 只实现 Claude Code，但接口从第一天存在。**

## 记忆

**记忆 / memory**
**存规则，不存对话。** 内容是：商户→分类映射、用户的每次纠正、个人语境词表（「我妈」= 家庭支出）、语音专有名词表。**不得把原始对话历史当作记忆持久化**（[`docs/prd/06-memory.md`](./prd/06-memory.md)）。

**这是唯一的复利**：第一个月 40 条改 8 条，半年后 40 条改 1 条。

**纠正 / correction**
用户在审核时对草稿做的修改。每一次纠正都是记忆的输入——「这家店应该归餐饮」下次就不用再改。

## 弱信号（v1 不做）

**弱信号采集**
从日历、git、浏览器历史、屏幕使用时间等处自动获取活动痕迹。**v1 明确不做**。未来做时的前置条件：默认全关、逐项授权、可随时关闭、结果只留本机、高敏数据（如窗口标题）在 UI 上明示敏感性（[ADR-0005](./adr/0005-voice-and-system-integration.md) §4）。

## 文档与流程

**sub-PRD**
一个能力一份的规格文档，扁平存放在 [`docs/prd/`](./prd/)。**本项目不用 ticket**——人写「要什么和为什么」，agent 出「怎么做」。

**回流**
把实现相对规格的偏离、澄清、新发现**回写到 sub-PRD**，版本号 +0.1。**实现证伪规格时先回写文档再改代码。** 口诀：**计划易失，决定回流**。

**零沉默原则**
任何两份 sub-PRD / 两次实施必须达成一致的东西（schema、契约、状态语义），要么**被决定**（标依据），要么**显式挂起**（标谁来决）。**唯一不允许的状态是沉默**——沉默会被每次实施用自己的假设填掉，且各填各的。
