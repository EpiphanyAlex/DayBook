# ADR-0003：Agent 运行时——自带 CLI、本地 MCP server 与可插拔后端

- **日期**：2026-08-06
- **状态**：已接受
- **决策者**：@maintainer
- **相关**：[ADR-0001 本地优先桌面平台](./0001-local-first-desktop-platform.md)、[ADR-0002 AI 永不直接写入](./0002-ai-never-writes-directly.md)、[`docs/prd/01-agent-runtime.md`](../prd/01-agent-runtime.md)
- **2026-08-08 修订**：仓库转为公开，决策者署名改为非具名 handle。**决策内容未变**——§2 论证「不按业务领域拆 agent」的跨域例句保留，它是该决定的载重论据。

## 背景

产品的成本模型建立在「**用户自带 AI 额度 → 边际成本为零 → 可以暴力啃任意格式截图**」上（[`docs/PRD.md` §3](../PRD.md) 支点 1）。传统记账 app 必须给每家银行写专用解析器——银行改格式就挂、长尾永远覆盖不到；按 API 计费的竞品算完账也会退回去写解析器。**只有让用户自己的额度承担 token 成本，才能对着任意截图直接说「读吧」。**

同时，用户要的不是「一个能调 API 的输入框」，而是「下达任务、它自己编排」。Claude Code 与 Codex 本身就是成熟的 agent runtime——多轮推理、工具调用、上下文管理全都现成。

三个待解决的问题：

1. 应用怎么把「数据库读写能力」交给这些 CLI？
2. 怎么保证 agent 不会绕过 [ADR-0002](./0002-ai-never-writes-directly.md) 的草稿区？
3. Anthropic 对第三方 agent 使用订阅额度的政策反复过（[`docs/PRD.md` §12](../PRD.md) 平台风险），怎么不被单一厂商绑死？

## 决策

### 1. 本应用本质上是一个本地 MCP server

**不让 agent 输出 JSON 再由应用解析，而是用 MCP（Model Context Protocol）暴露工具。**

MCP server 走 **stdio**，用 **`rmcp`**（官方 Rust SDK）实现，**在 Tauri 主进程内起**，不额外拉进程、不开端口（与 [ADR-0001](./0001-local-first-desktop-platform.md) 的「不开 localhost HTTP API」一致）。

```
┌─ React UI ──────────────────────┐   审核界面 / 两个视图 / 回顾
├─ Tauri (Rust) ──────────────────┤   进程管理、文件、SQLite
│    ├─ MCP server (stdio, rmcp)  │   ← agent 通过它读写数据
│    └─ agent launcher            │   ← spawn `claude -p` / `codex exec`
└─ SQLite + 截图目录 ─────────────┘
```

### 2. 单 agent + 多工具，不按业务领域拆

**一个 agent，两套工具，两张表。**

不按业务领域拆的理由：用户一句话经常跨域——「今天吃饭 180，明天交房租，上周那 400 是给我妈买茶叶」。拆成「记账 agent」和「事项 agent」就要先分派再合并，凭空多出一个错误面，而且闭不了环（分派错了没人纠正）。

**唯一该拆子 agent 的场景是上下文隔离**（例：解析一张含 60 笔的长截图，避免污染主上下文）。**按上下文拆，不按业务拆。产品运行时不引入多 agent 自主编排。**

### 3. 工具权限由代码强制，不靠 agent 自觉

- 记账工具在**代码层**只能写交易草稿表；事项工具只能写事项草稿表；修正工具带硬规则。
- **不得提供通用的「执行任意 SQL」类工具**，也不提供「任意文件写入」类工具。
- 工具签名本身就是权限边界——agent 拿不到越权的能力，不是「拿得到但被要求别用」。

这是 [ADR-0002](./0002-ai-never-writes-directly.md) 闸门 1 在工具层的落地：草稿区的隔离性由「agent 根本没有写事实表的工具」保证。

### 4. 后端可插拔，接口从第一天存在

支持的后端形态：`claude -p` / `codex exec` / 用户自备 API key / 本地模型。

**v1 只实现 Claude Code 一种，但接口从第一天就存在。**

**应用不打包任何厂商凭证、不提供第三方登录、不代理厂商鉴权。** 用户使用的是自己已安装并登录的 CLI；模型服务商的流量由该 CLI 自行发起，应用不代理、不转发、不记录（[ADR-0001](./0001-local-first-desktop-platform.md)）。

### 5. 控制流由代码决定

状态机、确认点、重试策略是**确定性的代码**；LLM 只做抽取、解析、分类与起草，**不做最终业务决策**。

例：「解析完是否入库」不是 agent 判断的，是代码在总额校验通过且人工确认后执行的。

## 理由

**为什么 MCP 而不是「agent 输出 JSON，应用解析」**：

1. **工具层强制隔离直接落地**——权限边界就是工具签名，不需要在解析 JSON 后再补一层校验。
2. **Claude Code 和 Codex 都支持 MCP**——可插拔后端白拿，同一套工具面对两个 CLI 都成立。
3. **多轮编排天然支持**——agent 可以「先查历史上这个商户归哪一类，再决定怎么起草」。JSON 输出是单向的，做不到。

**为什么 stdio 而不是 HTTP MCP**：stdio 没有端口、没有本机其他程序可见的攻击面，且生命周期天然绑定在子进程上——agent 退出，通道就没了。

**为什么在主进程内起而不是独立二进制**：`rmcp` 允许如此，省掉一层进程管理与版本同步。

**为什么可插拔接口不能推迟**：Anthropic 的政策已经反复过三次（2026-04-04 封禁 → 05 月改为 Agent SDK credits → 06-15 暂停该改动）。方向明确但未落地。等它落地再抽象接口，就是在压力下改架构。**但这条只作为工程对策，不写进产品叙事**——README 和产品定位里不需要反复强调。

## 后果

**得到**：

- token 成本为零，可以对任意格式截图做重解析
- 白捡成熟 agent runtime（多轮、工具调用、上下文管理）
- [ADR-0002](./0002-ai-never-writes-directly.md) 的隔离在工具层物理成立
- 厂商政策变化时换后端，不改架构

**付出**：

- 用户必须自己装好并登录 Claude Code 或 Codex——**这是一道真实的准入门槛**，产品不做任何简化（简化就意味着代理鉴权，违反本 ADR）
- 受制于用户订阅的用量限制。核心操作（多图 + 长上下文 + 多轮推理）恰好最烧额度（[`docs/PRD.md` §12](../PRD.md)）
- 不同后端的能力差异（尤其视觉解析）会导致体验不一致，v1 不做能力探测与降级

**对实现的硬性要求**：

1. MCP 工具集里不存在通用 SQL / 通用文件写入工具
2. 写事实表的代码路径不被任何 MCP 工具触及
3. agent 后端通过 trait / 接口访问，v1 的 Claude Code 实现不得成为其他代码的直接依赖
4. 代码里不出现任何厂商 API key、endpoint 或登录流程
