# ADR-0007：本地可观测性与日志分级 —— 为什么日志落盘，落什么，不落什么

- **日期**：2026-08-08
- **状态**：已接受
- **决策者**：@alex（产品负责人）
- **相关**：[ADR-0001 本地优先桌面平台](./0001-local-first-desktop-platform.md)、[`docs/prd/01-agent-runtime.md` §3.4](../prd/01-agent-runtime.md)、[`docs/prd/07-eval.md`](../prd/07-eval.md)

## 背景

**本 ADR 推翻了一条既有决定。** [01 Agent 运行时 §3.4](../prd/01-agent-runtime.md)（v0.1–v0.3）原文是：

> **日志**：子进程 stdout/stderr 采集到**内存环形缓冲**，供 UI 排障显示；**不落盘**（可能含截图内容片段）。

理由是隐私：agent 的输出里会带账目细节和截图内容。

但 2026-08-08 的设计评审要求两样东西，两样都以「日志落盘」为前提：

1. **遇到 bug → 查日志 → 变成可复现的测试** —— 进程一退内存缓冲就没了，没有任何东西可查
2. **回归测试** —— 要重放一次真实运行，必须先把那次运行录下来

同时评审确认了一个更硬的约束：**拿不到别人机器上的日志**。[`CLAUDE.md`](../../CLAUDE.md) 约束 2 把「遥测、崩溃上报」和云服务、账号并列禁掉了。所以日志只服务于**本机的作者自己**（v1 的主用户就是作者，见 [`docs/PRD.md` §7](../PRD.md)），对其他用户的唯一合法路径是他们**主动导出诊断包**。

## 决策

**日志落盘，分两级，位置在用户可见可删的应用数据目录内，永不出本机。**

### 两级

| 级别 | 默认 | 内容 | 用途 |
|---|---|---|---|
| **`trace`** | **开** | 工具调用的**名称与参数形状**、耗时、退出码、重试次数、状态机转移、agent 会话与后端标识、usage 元数据 —— **不含金额、不含原文、不含 prompt** | 日常排障；「哪一步慢了」「哪个工具被拒了」 |
| **`debug`** | **关** | `trace` 的全部，**外加**完整提示词、agent 原始输出、**完整的 MCP 工具调用参数** | 复现 bug、导出夹具 |

`trace` 的字段集借自 MeritAI 的 `docs/design-harness.md` §6（外部参考仓库，不在本项目内）：「每个任务单独记录 CLI 版本、任务配置、输入版本、退出码、耗时、usage 元数据和重试次数」——**注意那份清单全是元数据，一条内容都没有**。这正是分级的分界线。

### 落盘规则

- 位置：`<数据目录>/logs/`，与 SQLite 和 `evidence/` 同级——**用户看得见、能自己删**
- 一次 agent 会话一个文件，文件名含 `agent_session_id`
- **默认保留 N 天后自动清除**（N 的具体值随实现定，登记在 `01`）
- 结构化（JSONL），供脚本消费
- **绝不上传、绝不上报、绝不代理转发**。[ADR-0001](./0001-local-first-desktop-platform.md) 禁的是「数据离开本机」，不是「数据写进本机磁盘」——这个区分是本 ADR 成立的基础

### dogfooding 期间 `debug` 默认开

v1 的使用者是作者本人，机器是自己的，账目是自己的，没有第三方隐私问题。而**夹具导出依赖 `debug`**（见下），关着就等于没有飞轮。

### 为什么 `debug` 必须包含完整工具调用参数

因为 **agent 是非确定性的**。同一张截图重跑一次不会产出同样的草稿，所以「复现」不能是「重新调一次 agent」——必须是**重放那次录下来的工具调用序列**（工具名 + 完整参数），喂进系统，不碰模型。

这推出两种成本截然不同的测试：

| | 测什么 | 怎么跑 | 成本 |
|---|---|---|---|
| **eval** | 模型读得准不准 | 真调 `claude -p`，20 用例 | 烧订阅额度，本地跑，不进 CI |
| **回归** | 代码改了会不会挂 | **重放录好的夹具** | **零额度、确定性、可进 CI** |

而重放测的**不是模型**，是——**当 agent 读错时，我们的代码有没有拦住**。一条「把 168 读成 1680」的夹具，它的断言是「总额交叉校验必须报警」。闸门被谁改坏了，这条夹具立刻变红。完整规格见 [`07-eval`](../prd/07-eval.md)。

## 否决的替代方案

| 方案 | 否决原因 |
|---|---|
| 坚持不落盘（原 `01 §3.4`） | 飞轮与回归测试都不成立；bug 只能靠「下次再遇到时手动盯着看」 |
| 全量落盘，不分级 | 最好用，但每次日常使用都把完整账目细节和 prompt 写进磁盘。分级让「日常」与「取证」两种姿态分开，用户按需切换 |
| 只落盘不清除 | 长期累积到 GB 级，且旧账目细节无限期留存。保留期是隐私姿态的一部分 |
| 上报到远端便于分析 | 直接违反 `CLAUDE.md` 约束 2（遥测、崩溃上报明令禁止） |
| 落盘但加密 | 加密日志的密钥要放哪？（同一台机器上）。而威胁模型是「误上传/误分享」，不是「本机被入侵」——保留期 + 用户可删更对症 |

## 后果

**得到**：

- bug 可复现，且复现是确定性的（不依赖模型这次心情好不好）
- 回归测试不花额度、不依赖网络、不依赖 agent CLI 是否安装
- `trace` 常开意味着日常排障也有据可查，而它不含敏感内容

**付出（诚实登记）**：

- **`debug` 开着时，那次会话的账目细节与截图内容片段会写进磁盘。** 这是「要能复现 bug」的直接代价，无法两全。产品必须在 UI 上明示这一点——开关旁边写清「会记录完整账目细节」
- 夹具里是**真实截图与真实金额**，所以**本机夹具留本机、不进 git**（`.gitignore` 已挡 `/samples/`）。进仓库跑 CI 的必须是手工脱敏或合成的一小撮。**两套东西，不得混用**
- 多一个保留期清理任务要维护

**对实现的硬性要求**：

1. `trace` 级的写入路径上**不存在**金额字段、`evidence_text`、prompt 文本
2. 日志目录在应用数据目录内，不在系统临时目录或用户主目录的隐藏路径
3. 没有任何代码把日志内容发往网络
4. `debug` 开关的状态在 UI 上可见，不是一个只能改配置文件的隐藏项
